## 二、受控假上游（确定性的账务边界）

`go test -race ./...` 全部通过（16 组用例）。与 PRD 验收项的对应关系：

| 验收项 | 用例 | 结论 |
|---|---|---|
| 08-1 额度只够 1 个请求，同时发 5 个 | `TestQuotaNotDoubleSpentUnderConcurrency` | 1 个放行、4 个 402；到达上游的调用恰好 1 次；结束后预留为 0 |
| 08-2 多次并发调用的费用之和 | `TestConcurrentSettlementSum` | 20 个并发（流式与非流式各半）后，Key 已用 = 各请求应计费用之和 = 日志费用之和 |
| 08-3 各类结束方式 | `TestSettlementScenarios` | 上游 500：0 费用；调用前失败：0 费用；超时：待核实且保留预留；流式取消、断流：估算且 > 0；渠道切换：尝试 2 次只计 1 次；重复结算不生效；管理员核实后预留归零 |
| 08-4 在途时重启 | `TestRestartRecovery`、`scripts/verify_restart.sh` | 已结算不丢；未发往上游的释放；已发往上游的转待核实并继续占用；旧进程迟到的完成通知不改账；经核实接口处理后归零 |
| 08-5 Key 独立、无限额度、权限与限流 | `TestKeysIndependentAndUnlimited`、`TestAuthAndPermission`、`TestRPMLimit`、`TestConcurrencyLimit` | 通过 |
| 待核实超期 | `TestPendingAutoSettle` | 按预留上界自动结算并标“估算” |

`scripts/verify_restart.sh` 的实际输出（真正 `kill -9` 网关进程）：

```
1) 先完成一次正常调用（输入 100、输出 50 Token，应计 200 微元）：HTTP 200
   已用=200 微元, 占用=0 微元
2) 发起一个上游迟迟不返回的在途请求，然后 kill -9 网关进程
   崩溃前：已用=200 微元, 占用=314 微元
3) 重启网关（同一个 SQLite 文件），启动时自动执行恢复
   重启后：已用=200 微元, 占用=314 微元   ← 已结算费用未丢失；在途预留转为“待核实”，继续占用额度
   待核实预留 1 笔：…占用 314 微元，已发往上游=True；说明：服务重启恢复：请求已发往上游但未收到结果，费用待核实
4) 管理员通过正式接口核实：按实际费用 30 微元结算
   核实后：已用=230 微元, 占用=0 微元
5) 核实后 Key 可继续正常使用：HTTP 200
```

其他功能的用例：模型导入、别名、获取失败保留配置、收藏在重启后保留（`TestFetchModelsAndFavorites`）；
请求 ID 精确查询、CSV 导出、费用合计与翻页无关、按模型汇总（`TestLogsExportUsage`）；
视频（MiniMax / Seedance、成功与失败）、朗读、流式朗读、长文本配音、音乐、音色设计与复刻（`TestVideoTasks`、`TestSpeechMusicVoices`）；
控制台选择已有 Key（`TestConsoleKeySelection`）。

## 三、已知情况

- **音乐生成未能做真实验收**：当前 MiniMax 账号没有音乐接口权限（上游 410）。需要一个有权限的账号后，在“音乐生成”页直接重试即可。
- 验证过程中修过两处：`MiniMax-H3` 起初被按名称归类为聊天模型（已修正分类规则）；音色复刻/设计的日志起初记在语音模型名下，
  已改为记在 `voice-clone` / `voice-design` 下，并把本库里此前的 2 条日志的模型名手工改成了新口径（费用未动）。
  两条音乐失败的旧日志状态仍显示“成功（已受理）”，新版本会在任务失败时把日志同步标为失败。
- 控制台的主题、各页面在浏览器中做了走查；没有做移动端与多浏览器的系统测试。Safari 等不支持 MP3 MediaSource 的浏览器，
  流式朗读会退化为“生成完再播放”（页面有提示）。
